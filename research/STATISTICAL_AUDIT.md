# Statistical and timing audit — 2026-11-08

이 문서는 기존 첫 실증 MVP를 고정한 사후 감사다. 원래 모델·특징·필터·분할·시차·threshold를 변경하지 않았다. 기존 `results/summary.json`, 예측 CSV와 그림은 유지했다. 추가한 가격 변화 규칙은 요청된 진단용 Baseline이며 새로운 alpha 모델 탐색이 아니다.

**판단:** 현재 자료에서 OBI의 조건부 방향 예측과 미래 수익률 간 양의 관계는 관찰된다. 명백한 미래 정보 참조나 분할 경계 누수는 검사한 경로에서 발견하지 않았다. 그러나 42분 한 세션, 이미 살펴본 테스트, 9개의 60초 테스트 블록으로 일반적 예측 우월성·견고한 유의성·거래 수익성을 확정할 수 없다. Accuracy와 Balanced Accuracy의 불확실성은 다르므로 아래에서 구분한다.

## 1. 표본 수 감소

95개 입력 파일에는 두 세션의 15,620행이 있다. 짧은 다른 세션 325행을 제외한 연구 원본이 15,295행이다. 선택 세션의 유효 호가·중복/비정상 검증 이후·이벤트별 Feature 계산 이후는 각각 **15,295행**이며 이 단계에서 제거된 행은 0이다. 양쪽 가격/수량·원문·시각·해시를 검증했다. 15,295개를 2,562개 1초 격자로 요약하는 것은 비정상 데이터 제거가 아니라 관측 단위 변경이다. 동일 초에 도착한 여러 BBO 중 해당 격자까지 받은 마지막 상태만 사용한다. 신선도 기준으로 격자 4개를 제외하여 유효 Feature 격자는 2,558개다.

### 미래 호가의 정확한 규칙

`M(u) = mid of latest valid BBO with receive_timestamp <= u`, 단 최신 상태가 stale/invalid이면 이전 정상값을 되살리지 않는다. `u=t+h` 이후에 도착한 호가는 사용하지 않는다. 반대로 목표 시각 이전 마지막 호가이므로 정확히 목표 시각에 새 호가가 존재할 필요는 없다. 이 정의는 “목표 시각에 연구자가 알고 있던 mid”이지 matching engine의 연속 가격 경로가 아니다.

1초 유효 라벨 2,554개 중 종료 호가가 t 이후 새로 도착하지 않은 경우는 **42개**, 전부 0 수익률이다. 종료 호가의 exchange timestamp가 t를 넘지 않는 경우는 79개이며 역시 전부 0 수익률이다. 비영 방향 라벨에서 종료 호가는 모두 receive/exchange 시각 기준 t 이후이며, 모든 시차에서 target 뒤 수신을 이용한 사례는 0이다. 추가 필터로 이 사례들을 제거하지 않았다.

### 지연·신선도가 해석에 주는 영향

Exchange→Receive 차이는 최소/중앙/95%/최대 **0.155/0.261/0.393/0.900초**다. UTC 정합성 인증이 없으므로 이를 순수 네트워크 지연으로 단정하지 않는다. 유효 Feature의 수신 나이는 중앙 0.112초·95% 0.656초·최대 1.856초이고, exchange 기준 나이는 최대 2.120초다. 두 개의 별도 2초 필터는 exchange age<=2초라는 단일 조건이 아니다.

| 라벨 시차 | 비영 라벨의 실제 시작·종료 호가 수신 간격 min / median / max | 종료 호가가 t 이후 도착하기까지 min / max |
|---|---|---|
| 1s | 0.764 / 1.033 / 2.463s | 0.643 / 1.000s |
| 5s | 3.711 / 5.016 / 6.478s | 3.537 / 5.000s |
| 10s | 8.643 / 10.009 / 11.425s | 8.144 / 10.000s |

따라서 1초 라벨도 두 실제 호가 사이의 시간은 약 0.764–2.463초로 다르다. lag와 staleness는 무변화 비중·목표 정렬·초단기 성능을 바꿀 수 있다. 현재는 receipt-clock 연구이며 exchange-clock 1초 예측력이나 실행 latency 우위를 주장하지 않는다. 1초 격자 사이에서 발생하고 다음 격자 전에 회복된 일시적인 통신 공백까지 완전히 검열하는 규칙도 아니다. BBO가 블록에서 변할 때만 전송되는 채널이므로 조용한 구간을 곧바로 손실로 분류할 수 없다.

## 3. 동일 테스트 표본의 모델 비교

Training majority baseline은 training up-rate를 모든 행에 적용하며 세 시차 모두 상승을 예측한다. **테스트 자료를 보고 다수 클래스를 다시 고르지 않는다.** 1초 test의 사후 다수 클래스는 하락30/56(0.536)이지만 이것은 진단용 숫자이며 사용 가능한 학습 Baseline(상승, Accuracy0.464)과 다르다.

가격 변화 Baseline은 `sign(M(t)−M(t−1s))`를 따른다. 변화가 0이거나 이전 격자가 부적격이면 training majority로 돌아간다. 입력은 t까지 알려져 있으며 미래 수익률/테스트 정답으로 fallback을 선택하지 않는다. test의 무변화 fallback은 1/5/10초에서 39/158/262행, 이전 격자 결측 fallback은 모두0행이다. 규칙 점수 0/1/prior는 보정된 확률이 아니며 AUC는 순위 진단이다. OBI/결합 모델의 학습 조건은 원본 그대로다.

## 4. 블록 CI가 얼마나 안정적인가

블록은 고정 test 시간 경계에서 시작하며 무방향/0 수익률 때문에 비어 있는 시간 블록도 보존한다. 동일 block index로 모델과 Baseline을 함께 재표본화한다. 30/60/120초와 시작점을 반 블록 이동한 민감도를 **모두** 기록했다. 기존 결과와 같은 30/60초 origin CI도 재현된다.

|---|---|---|---|
| 1s | 18/16 | 9 (6) | 5 | 0/55 |
| 5s | 17/15 | 9 (6) | 5 | 164/186 |
| 10s | 17/15 | 9 (7) | 5 | 291/300 |

OBI의 lag-1 상관은 약0.910이다. 1초 라벨도 기계적 중첩은 없지만 Feature와 가격 상태가 지속돼 독립 표본으로 볼 수 없다. 5/10초에는 인접 테스트 label 쌍 대부분이 겹친다. 60초는 최대10초 horizon보다 길어서 중첩을 일부 묶는 출발점이나, 충분한 block length라고 입증되지 않았다. 약8.5분 test에서는 9블록뿐이고 중첩이 블록 경계를 가로지를 수도 있다. 1,000회 resampling은 9개의 정보 단위를 늘려주지 않는다.

## 5. 독립 실행·재사용·수정 범위

`src/obi_research/features.py:6`에서 동일 패키지의 `legacy_book.book_features`를 가져온다. legacy_book은 Liquidation Gravity의 원본 함수와 byte-identical이다. 원본 프로젝트 import/절대경로/가상환경이 필요한 구조가 아니다. raw BBO와 recorder logs는 데이터 입력으로 필요하며 코드 의존성이 아니다.

새 Python3.11.6 환경에서 `pip install -e ".[dev]"` 설치, 다른 임시 폴더로 95개 BBO와 로그2개 복사, `/tmp`에서 CLI 전체 실행을 확인했다. 원래 Python3.13 환경과 NumPy/SciPy 버전이 달라도 audit/session/horizons 값이 같고 metrics·예측·분위 CSV·그림4개를 합한 9개 파일이 byte-identical했다. 환경/코드 metadata가 달라지는 전체 summary.json을 byte-identical이라고 주장하지 않는다. [독립 재현 기록](../results/audit/independent_reproduction.json).

수정은 `research/run.py`에 `--bbo-dir`, `--recorder-dir`, `--output-dir`를 추가하고 파생 Parquet를 지정 출력 폴더로 보내는 입출력 정리에 한정했다. 원본 LG 폴더 구조를 통째로 재현해야 하는 불편과 기존 결과 덮어쓰기 위험을 줄였다. `--source-root` 호환 경로는 유지하며 기본 실험 수치·필터·모델 로직은 그대로다. 감사는 별도 `research/audit.py`와 `results/audit/`에 저장한다.

실제로 발견한 재현 안내 오류: 원래 README는 Python3.11+에 원래 고정 requirements를 안내했지만 NumPy2.5.3와 SciPy1.18.1은 Python>=3.12를 요구한다. 기본 설치는 package dependency resolver를 사용하도록 고쳤다. 원래 requirements는 Python3.13.15 실험 환경 기록으로 보존하고 Python3.11 감사 환경의 freeze는 requirements-audit.txt에 별도로 기록한다. Feature/라벨 계산 오류는 이 감사에서 발견하지 않았으므로 그 코드는 수정하지 않았다.

공개 clone에서 계산·시점 테스트와 저장 test 예측 지표 검산은 가능하다. **정확한 역사 입력을 제공하는 공개 다운로드 경로와 재배포 허가는 확인되지 않았다.** 따라서 전체 실증 재현은 별도 입력 확보가 필요하다. 공식 문서·약관을 확인한 범위와 새 공개 BBO 구독 경로는 [DATA_ACCESS.md](DATA_ACCESS.md)에 명시했다. 새 구독은 이 과거 결과를 재현하지 않는다.

## 6. 추가 자료와 결론의 범위

다음 날짜 43.6분 별도 세션에서 BBO16,945개·격자2,616개 중2,614개 유효 상태를 확인했다. 수익률/모델 점수는 보지 않아 향후 고정모델 검증 후보로 남겨뒀다. 다른 세션이라고 통계적 독립성이 보장되는 것은 아니며 현 기록만으로 loss-free coverage도 보장되지 않는다. [품질 기록](../results/audit/heldout_session_quality.json). 전체28세션 중 일부는 음수 lag나 큰 지연 때문에 별도 검증이 필수다. 같은 최초 세션의 나머지 약104분은 보조 분석에는 유용하지만 독립 세션으로 세지 않는다.

권장 다음 단계는 먼저 이 후보에 원래 training으로 고정한 모델을 적용하고, 이어 5–10개 날짜에서 하루1–2시간 이상 관측하는 것이다. 이는 최소한의 실용적 계획이지 검정력 보장이 아니다. 2시간 외부평가는 최대120개의1분 블록을 제공할 수 있지만 실제 유효 독립 단위는 더 적을 수 있다. 독립 날짜/세션별 변동을 보고 나서 목표 효과·block 의존성을 반영한 power/기간 설계를 한다. 수집기는 재사용하고 대규모 인프라를 만들지 않는다. 필요한 필드·기존 CLI·타임스탬프 보존 방침은 DATA_ACCESS.md에 있다.
